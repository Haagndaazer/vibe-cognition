## PROBLEM

Shared cognition graphs go stale-wrong across teammates' machines: nodes reference one user's absolute project root, tool choices, and machine setup, which silently mislead every other reader. The fix needs per-user durable facts (hostname, OS, project root, tool preferences) stored in the shared graph, per machine, without inflating the shared journal. Person-node metadata is the wrong home: `update_node` journals the ENTIRE metadata dict per call (storage.py:301-317 convention, confirmed at cognition_tools.py:2299 for person updates), so accumulating fact history there is O(n²) journal growth — and session-frequency fact writes make that unacceptable.

## CURRENT MECHANICS (verified at branch fix-test-chroma-leak, 2026-08-14)

- Journal write path: `append_journal_line(path, line)` (journal_io.py:114) is already path-generic — per-person files need no new low-level IO.
- Hydration/catch-up state is single-journal-path: `self._offset`, `self._journal_hasher` sha256 prefix hash, `_journal_mtime_ns` — all instance fields bound to `self._journal_path` (storage.py:84-93); rehydrate-reset detection in `_catch_up` (storage.py:993-1093) and the WP-5 deferred-entry retry (storage.py:1096-1126). Per-person files need per-file instances of this state. The main journal's hot-path discipline: a single cheap `stat()` gates everything — size AND mtime unchanged ⇒ one syscall, no read (storage.py:1042).
- `append_journal_line` creates the FILE (`O_CREAT`) but NOT parent directories (journal_io.py:114-143); `.cognition/` itself is mkdir'd by storage init (storage.py:125).
- Git hygiene: GIT_HYGIENE_VERSION = 5 (git_hygiene.py:54). ## DESIGN

**New directory `.cognition/people/` (COMMITTED), one JSONL file per identity.** Filename = slug of the casefolded email, deterministically encoded (percent-style encoding of non-`[a-z0-9._-]` bytes with LOWERCASE hex digits — pinned explicitly, since encoder libraries legally differ on hex case and an unpinned case means two implementations mint two files for one person on a case-sensitive filesystem; then if the encoded form exceeds 40 chars, truncate to 24 + `-` + first 12 lowercase-hex chars of sha256 of the casefolded email). Casefold BEFORE encoding (topology-dependent-collision guard: `Alice@X.com` and `alice@x.com` must be one file on case-sensitive Linux too). Lossy sanitize-and-strip is banned — `alice+a@x` / `alice+b@x` colliding is silent data merge, worse than a crash. Total path stays far under Windows MAX_PATH.

**Registration stays in the main journal; ONLY fact deltas stream to the person file.** The person node (graph identity, search, edges, profile fields, profile_history) is untouched by this WP. The person file holds environment facts exclusively.

**Delta primitive — the load-bearing new convention.** Person-file lines are NOT `update_node`-shaped (that convention re-journals whole dicts — the exact O(n²) this WP exists to kill). New action type:
`{"action": "fact_set", "email": <casefolded>, "machine": <machine-key>, "key": <fact key>, "value": <JSON value>, "old": <prior value|null>, "at": <aware-UTC ISO>, "by": {name, email}, "from_agent": bool}`
and `{"action": "fact_delete", ...same envelope, no value}`. Hydration folds deltas in file order into a facts map; the file IS the audit trail (no separate history array — every line is one change, so the O(n²) shape is structurally impossible, not just avoided).

**Facts hydrate into a per-email registry OUTSIDE the graph** (precedent: `_reference_index`, storage.py:80 — non-graph state built during replay). Facts map: `{email: {machine_key: {facts...}}}`. This makes cross-file replay ordering a NON-problem by construction: fact state never references graph nodes, so "fact delta replayed before its person's registration node" cannot dangle — a person file with no registration node is a first-class legal state (facts for a not-yet-registered identity; surfaced by read tools with `registered: false`, never an error). `cognition_get_person` joins graph node + facts registry at read time.

**Machine key.** Casefolded hostname (`platform.node()`), collisions only matter within one person's file. Cap: max `env_fact_machine_cap` (default 10) machine entries per person; at cap, a write for a NEW machine is rejected with a retryable error naming the prune tool — never silent LRU eviction (evicting a still-real laptop's facts silently is data loss; the human prunes).

**Self-only writes (decision 29faeeca5190).** New tools `cognition_set_env_fact` / `cognition_delete_env_fact` / `cognition_clear_env_facts`: the target email is ALWAYS the server-resolved git identity — there is no email parameter at all (impersonation-resistant by construction, mirroring register_person's self path). Unresolvable git identity ⇒ retryable error, never a guess. Profile fields keep the existing anyone-may-update path in the main journal — the two surfaces don't overlap.

**Bulk removal (peer-review MEDIUM; the removal-on-request ruling made concrete).** `cognition_clear_env_facts(machine=None)`: with `machine` clears every fact for that one machine of YOUR identity; without, clears ALL your facts across all machines. Emits one `fact_clear` delta line `{"action": "fact_clear", "email", "machine": <key|null>, "cleared_keys": [...], "at", "by", "from_agent"}` (keys enumerated in the line so the audit trail shows exactly what was removed — never an opaque wipe). "Please delete everything you've stored about me" is one call, not an enumerate-and-loop the agent can get wrong.

**Disclosure (decision cb8605c710fb) — tool-result half.** Every successful set/delete returns a `disclosure` field: human-readable "Stored to your identity: <key>=<value> (machine <m>). You can ask for it to be removed at any time." — the tool contract REQUIRES the agent surface it. (Prime-side loud listing is WP-B; the delta lines carry enough to build it.)

**Read surface.** `cognition_get_person` response gains `environment: {machine_key: {...}}` + `registered` flag. New `cognition_list_env_facts` (self or any email — reads are open; only writes are self-only) so divergence checks in WP-B have a query path.

**Concurrency + merge.** Appends use the existing `append_journal_line` (O_APPEND semantics). `.gitattributes` gains `.cognition/people/*.jsonl merge=union` via the hygiene writer. Single-writer-per-file (self-only) makes union-merge safe the same way it is for the main journal, and makes future compaction of a person file safe (out of scope this WP).

**Catch-up (peer-review HIGH applied: directory-mtime gate).** Per-file `_offset`/hasher/mtime state in a small per-file struct, keyed by slug. The hot path stays O(1): stat the `people/` DIRECTORY first — dir mtime changes on file creation on both NTFS and POSIX — and only `listdir` when it changed (a teammate's first file appearing after a pull is caught by the dir-mtime change); known files are then individually stat-gated exactly like the main journal (size+mtime unchanged ⇒ one syscall, no read, storage.py:1042 discipline). Every tool call is a catch-up caller, so the no-change cost is a handful of stats regardless of team size — never O(N_people) reads. Truncation/rewrite detection per file mirrors the main journal's (size < offset OR prefix-hash mismatch ⇒ full re-fold of that file only — never a global rehydrate).

**Flush protocol + docs.** topology-guide.md updated: the flush checklist covers `.cognition/journal.jsonl` AND `.cognition/people/*.jsonl`; snapshot_cli docs updated to say it applies per-file. This is a REQUIRED, ordered part of the WP (docs land in the same PR), not a follow-up — a runtime-growing file set the manager's checklist doesn't know about is the branch-clobber incident class reintroduced.

**Kill switch.** None in this WP — WP-A adds no automatic behavior (writes only happen when a tool is called). `VIBE_COGNITION_NO_AUTO_FACTS` ships with WP-B's auto-capture.

**Config.** `env_fact_machine_cap: int = 10` in Settings. No prime knobs (WP-B).

**What does NOT change.** Main-journal format, person-node shape, profile update path, prime output (byte-identical — WP-B owns prime), dashboard (except get_person passthrough if trivial), no gitignore entries (people files are COMMITTED; `*.lock` already ignored).

## ACCEPTANCE

- Delta-only: a fact_set journals exactly ONE line containing only that change; setting the same key to the same value journals NOTHING (no-op suppression — explicit test); 100 updates to one fact produce 100 lines, not 100 growing snapshots (anti-O(n²) test asserts file size linear — WITH fails-before proving the test catches a whole-map-per-write implementation).
- Bulk removal: `clear_env_facts(machine=X)` removes exactly that machine's facts, others untouched; no-arg clears all; cleared_keys enumerated in the delta line; clearing an already-empty state journals nothing.
- Catch-up cost: benchmark at N=50 and N=100 person files — no-change tool call performs O(1) stats (dir gate) and zero file reads; assertion on syscall/read count, not wall-clock.
- Self-only: set/delete always target the resolved identity; no email param exists; unresolvable identity ⇒ retryable error, nothing written.
- Slug: casefold-before-encode (Alice@X ≡ alice@x, one file); `alice+a@x` ≠ `alice+b@x` (distinct files); long/unicode email ⇒ deterministic bounded filename; round-trip stability test; hex-case determinism test (encoded slug is byte-identical across runs and matches the pinned lowercase spec).
- Fresh project: first env-fact call with no `.cognition/people/` dir yet creates it (`mkdir(parents=True, exist_ok=True)` before first write — append_journal_line does NOT create parents) and succeeds.
- Hydration: facts fold correctly (set, overwrite, delete, per-machine isolation); person file WITHOUT registration node ⇒ `registered: false`, no error; registration without person file ⇒ empty environment; new file appearing between catch-ups is picked up; per-file truncation ⇒ that file re-folds, graph untouched.
- Concurrency: two threads appending to DIFFERENT person files interleave safely; union-merge of two divergent copies of one file loses no lines (both-sides-append fixture).
- Machine cap: 11th machine rejected with retryable error naming the prune path; existing machines keep writing at cap — WITH fails-before proving the test catches an off-by-one/never-firing cap check.
- Disclosure: every successful write's response carries the disclosure string (schema-level test).
- Hygiene: GIT_HYGIENE_VERSION 6; v5-stamped repo gains the `.gitattributes` glob on next init (fails-before both sides); people files NOT gitignored.
- Windows: slugged paths well under MAX_PATH; hostname casefolding on mixed-case Windows hostnames.
- Fails-before on: no-op suppression, self-only enforcement, slug collision pair, registered:false join, merge=union glob presence, anti-O(n²) linear-size, machine-cap rejection.
- Docs: topology-guide flush section, README, SKILL.md, readme.py COGNITION_GUIDE, CHANGELOG [Unreleased]. Tool-surface self-sufficiency audit re-run (4 new tools) per workflow 67751ebc39bd.
- Implementer notes (peer-review LOWs): GIT_HYGIENE_VERSION 6 is the FIRST bump touching the `.gitattributes` writer — `_needs_gitattributes`/`_write_gitattributes` currently hardcode the single journal.jsonl rule and must be generalized to two rules; do not copy the gitignore-bump checklist verbatim. `mkdir` parents before first people-file write (see ACCEPTANCE).
- Gate: standard — isolated worktree, pinned commit, independent pytest+ruff, journal untouched on branch. Version bump: user-facing ⇒ pyproject.toml + plugin.json bump, release per marketplace procedure (Loki re-pin).

## REJECTED ALTERNATIVES (record)

Facts in person-node metadata (rev-1 design): O(n²) whole-metadata journal rewrites, confirmed in code. New `environment` node type: config-not-knowledge — no embedding/edge/supersession value; enum + tool + dashboard + inert-type costs for a KV store. Machine-local-only storage: kills divergence detection, the feature's whole point. Facts routed through `update_node` convention into the person file: reintroduces O(n²) at smaller n. LRU eviction at machine cap: silent data loss; human prunes instead. Email parameter with an ACL check on write tools: parameter-that-must-match is impersonation surface; no-parameter-at-all is structurally self-only. Username-scrubbing/reduced-signal paths: fragile parsing, company trust domain (Colton ruling). Separate history array per fact: the delta file IS the history.

## KNOWN LIMITS (document)

Facts are repo-scoped: machine facts (OS, hostname) re-recorded per project — accepted redundancy, cheap at delta granularity. Hostname as machine key: corporate-imaged shared hostname templates collide within a person's own map (self-harm only, cap + prune is the remedy); ephemeral container/CI hostnames burn cap slots (the rejection error is the backstop, and WP-B's capture path will skip capture when a CI env is detected). Reads are open to all teammates (by design — divergence detection needs them); "no private-by-default facts" is Colton's explicit ruling with loud disclosure as the control. Deleting a fact removes it from hydrated state but the delta line persists in git history (same posture as every journal write; disclosed in tool docstring). Compaction of person files: deferred (safe under single-writer, not needed at delta sizes). Disclosure interim: between WP-A shipping and WP-B shipping, disclosure has NO server-enforced surface — the tool-result field relies on the calling agent relaying it (same trust-based pattern as the edge-authoring convention); WP-B's prime listing closes this. Orphaned fact files: removing a person node (cognition_remove_node) does NOT touch their `.cognition/people/` file — facts persist as a permanent `registered: false` entry until the person themselves runs `clear_env_facts` or the file is manually deleted; documented, with removal-tool guidance pointing at the person-removal moment as the natural cleanup prompt.
